# 多节点容量扩展

XXGate 支持一个入口和多个工作节点共享 PostgreSQL。每个账号固定归属一个工作节点；账号并发、会话内线程互斥、排队、OAuth 刷新和出站连接池都在所属节点内执行。入口提供统一 Web、API 地址和会话路由。

## 配置

未设置 `XXGATE_ROLE` 时继续使用单节点模式，默认节点 ID 为 `default`。

| 环境变量 | 含义 |
| --- | --- |
| `XXGATE_ROLE` | `router`（入口）或 `worker`（工作节点） |
| `XXGATE_NODE_ID` | 稳定、唯一的节点 ID，1–64 个 ASCII 字母、数字、下划线或连字符 |
| `XXGATE_NODE_URL` | 集群其他节点可访问的本节点 HTTP(S) origin，不含路径、查询参数或认证信息 |
| `XXGATE_CLUSTER_TOKEN` | 所有节点一致的内部认证密钥，至少 32 字节；独立于对外 API Key |
| `DATABASE_URL` | 所有节点连接同一 PostgreSQL 数据库 |
| `XXGATE_DB_POOL_SIZE` | 每个进程连接池大小，默认 24；应给迁移、监控和管理员连接留余量 |
| `XXGATE_MASTER_KEY` | 所有节点保持一致，沿用原凭证加密主密钥 |

节点之间应通过私网或 HTTPS 通信，工作节点端口不对公网开放。Web 和 API 客户端统一使用入口地址。配置的节点 URL 由部署方提供，不能通过公共请求覆盖。

`compose.cluster.yaml` 提供入口、两个工作节点、一个数据库的完整示例，只使用已构建的镜像。新建示例会使用独立的 `xxgate-cluster` 数据卷，不会自动连接现有生产数据库。不同主机部署时，在每台主机配置同一数据库地址和各自可互访的节点 URL。

生产镜像必须在本地构建并测试 Linux amd64 版本，导出后带 SHA-256 校验和传输。生产只校验、加载镜像和使用 `docker compose up -d --no-build` 启动，禁止在生产编译。

## 停机升级与显式迁移

服务启动只检查 schema 版本和校验和，不会自动迁移。旧进程、所有入口和工作节点均停止后，使用同一个发布镜像执行 `xxgate-server migrate`，完成后再启动服务。`xxgate-server check-schema` 可只读检查版本。迁移与运行进程使用互斥的数据库门闩；旧版单实例正在运行时迁移也会拒绝执行。

`compose.cluster.production.yaml` 是复用现有生产库的配置，不创建或删除数据库卷，沿用 `xxgate-private`、`code-internal`、内部 `xxgate` 别名和回环端口 8797。切换前停止原 `xxgate` 容器并从 `code-internal` 断开，避免同名 DNS 别名指向旧容器。随后运行：

```sh
docker compose --env-file cluster.env -f compose.cluster.production.yaml run --rm --no-deps entry migrate
docker compose --env-file cluster.env -f compose.cluster.production.yaml up -d --no-build --wait
```

迁移 0021 改变统计表唯一键，属于不兼容升级；不能只换回旧镜像。通常先备份，若用户明确接受无备份停机升级，可以跳过备份；失败后保留原卷并修复向前，不自动清空数据库或恢复旧镜像。`/healthz` 检查进程和数据库，入口的 `/readyz` 还要求有在线、接收新会话的工作节点；空载新集群在添加启用账号前可能尚未 ready。

## 账号和管理

迁移 0021 将已有账号、会话归属、请求及小时汇总归属到 `default`，保留原凭证、Key 和记录。升级时先停止旧版单实例；通常备份数据库与原部署配置，用户明确接受无备份升级时可跳过数据库备份，再显式迁移并运行新版本；让承接历史账号的工作节点继续使用 `default`。入口使用另一个 ID，不能复用已有账号的节点 ID。

在统一 Web 的“节点”页可查看心跳、状态、容量、并发、排队和配置版本。添加/导入账号时选择所属节点。账户详情、配置、启停、刷新和重新授权会自动发送到账号所属节点。OAuth 流程归属持久化，即使切换页面中的操作节点，回调仍送到原节点。已经开始但所属节点重启的 OAuth 流程需要重新开始。

账号列表、模型目录、分组成员、历史请求与用量查询由入口统一读取。请求记录包含 `node_id`，支持 `GET /api/admin/requests?node_id=...`；用量汇总支持 `GET /api/admin/dashboard?node_id=...`。未指定节点时查询整个集群。实时监控、队列和批量模型同步使用顶部选择的操作节点。

此版本的账号归属固定，不提供在线搬迁。增加容量时，把新账号添加到新工作节点。不要把同一上游账号重复导入不同节点；数据库写入会检查重复归属。

## 路由与故障语义

- 新会话先按 Key 分组、模型、客户端来源与 WebSocket 要求筛选账号所在节点，再按已上报的并发、排队及容量选择节点。同等负载轮转选择。
- `Key ID + 客户端 session_id` 的节点归属通过唯一约束原子确定；并发首次请求共享同一结果。身份解析沿用现有协议，包括正文中的身份字段。无稳定会话身份的请求独立选择节点。
- 同一会话的后续请求固定到原工作节点。节点内仍遵守原有账号粘连和绑定代次规则。节点满载不触发跨节点迁移。
- 节点每秒上报状态，超过 10 秒未上报视为离线。协调查询失败时暂停新派发，恢复后自动解除该暂停；连续失败 30 秒后停止节点。独占锁连接明确丢失或 boot ID 被替换时立即停止，以防同一账号被两个进程同时使用。节点失联时已有会话明确失败，不转到其他账号池重放；新会话会避开离线节点。原节点恢复并使用相同 ID 后可继续处理原会话。
- 已有会话的模型或 Key 分组改变后，仍由原节点判断资格；原节点没有符合条件的账号时明确拒绝，不自动跨节点搬迁上下文。
- SSE 响应逐段转发并保持背压。原生 WebSocket 入站继续逐消息校验，每条消息通过所属工作节点执行；上游 WebSocket 连接归属工作节点。入口连接关闭时通知工作节点释放相关连接。
- 入口到工作节点的内部转发不跟随重定向、不重试生成请求。HTTP→WS 的受限 HTTP 回退在原工作节点、原账户内执行，审计记录两次上游尝试；节点故障不能无缝续接在途生成。

## 配置与持久化

每个节点只加载自己的账号与绑定，只有账号所属节点能够修改账号状态。节点 ID 有独占数据库锁；独占锁连接丢失会停止该节点。普通协调查询的短暂故障有上述恢复宽限期。启动恢复只终结本节点的遗留请求，保留其他节点在途记录。

Key 和运行配置在数据库共享。管理操作推送刷新通知，节点每秒检查配置版本以补偿遗漏；派发前再次查询 Key 的启用和分组，防止排队请求使用过期授权。`global_max_inflight` 表示每工作节点的总并发上限，内存与正文读取限制也按节点生效；集群容量由各节点共同提供。入口本身同样执行正文大小和内存准入控制。

额度查询等账号任务只处理本节点账号。数据库清理使用独占维护锁避免重叠执行。历史统计统一写入数据库，小时汇总包含节点维度，故障恢复保持幂等终结。不会把提示词、输出正文或响应流逐片段写入数据库。

## 验证

运行 `XXGATE_TEST_PG_BIN=/path/to/postgresql/bin python3 scripts/test.py cluster_gateway_contract`，测试程序创建临时 PostgreSQL 集群和独立 schema，启动真实 HTTP 入口及两个工作节点。

扩容验收应测量并发吞吐、排队时间、首字延迟、入口内存和数据库连接/写入负载。多节点可以减少资源争用和排队，但不会提高上游模型本身的生成速度，也不承诺吞吐与节点数量线性增长。
