# XXGate 设计基线

本文汇总讨论确认的需求与规则。首版工程已开始实现；具体实现选择、已完成测试与尚待真实上游验证的项目见 [实现与验证记录](implementation.md)。

“待确定”表示尚未选择的产品或运行参数；“待验证”表示需要源码核对、协议实验或集成测试确认的能力，不代表已实现或已保证可用。

## 1. 定位与范围

- Rust 网关，首版面向单机、数百个 ChatGPT 账户、上百路并发。
- 通过 OAuth 托管账户，网关管理凭证及其正常刷新。
- 接入方可以是 Codex、sub2api 或其他提供 Codex 协议身份的客户端。
- 身份契约以 Codex `0.153.4` 为基线，不识别或管理中间代理的真实用户，不推断代理是否修改过身份。
- sub2api `0.2.1` 是已知接入场景，不构成独立身份或用户管理契约。
- 仅管理员登录；对外签发 `sk-` 格式的网关 Key。
- 当前只考虑 Responses 协议的 HTTP/SSE 请求，不使用 WebSocket。
- 支持文本、图片输入、图片生成和编辑；具体 OAuth 上游能力待验证。
- 统计输入、输出及相关 Token 明细，支持账户级统计、自定义模型价格、Fast 额外计价。
- 价格直接使用人民币，不引入汇率换算。
- 强调请求溯源，只保存元数据、用量与脱敏错误，不保存提示词、模型输出或图片正文。

为未来 Claude、Gemini 等上游预留独立的入站协议和提供方适配边界，复用核心调度、身份代次、计量与观测能力。当前仍只实现 Codex 接入，不把其他厂商、原生入站协议或订阅 OAuth 托管列入首版能力承诺。扩展契约见 [代码模块规划](modules.md) 第 12 节。

## 2. 核心约束

1. 每个入站请求默认最多发起一次上游请求；仅第 8 节定义的加密推理恢复允许同账户、同绑定补发一次，总计最多两次。
2. 不实现通用失败重试、自动重连、授权恢复后的生成重放或失败后切换账户补发。
3. 客户端可以自行重新请求；每次入站请求独立记录，按当前会话绑定调度。
4. 同组存在可用账户但并发满载时限时排队。没有可用账户立即拒绝；已绑定账户并发满时等待原账户，不因满载迁移。
5. 账户停用后，尚未发送的请求可以迁移到同组其他可用账户；迁移后整套上游身份重新构造。无同组迁移目标立即结束等待。
6. 客户端会话与线程标识保持稳定，上游标识由网关管理映射。
7. 配置保存后立即热更新，覆盖已排队和在途请求适用的控制规则。
8. 每个 Key 只属于一个路由分组，账户可加入多个分组；请求和账户迁移不能跨出 Key 当前分组。Key 改组后重新建立绑定代次，原组排队请求返回分组已变更错误。

## 3. 术语

统一术语及易混淆概念见 [CONTEXT.md](../CONTEXT.md)，以下保留设计阅读所需的简表。

| 术语 | 含义 |
|---|---|
| 网关 Key 命名空间 | 用于隔离入站会话标识的凭证范围，不是终端用户身份 |
| 客户端会话 | Codex 提交的 `session_id`，作为账户粘连单位 |
| 客户端线程 | Codex 提交的 `thread_id`，区分会话内具体线程 |
| 账户运行时 | 账户凭证、出站客户端配置、并发占用及调度状态 |
| 绑定代次 | 一次会话到账户的绑定及其独立上游身份命名空间 |
| 请求 | 一次入站 HTTP 调用，拥有独立的网关 `request_id` |
| 上游尝试 | 本次请求对官方的一次实际调用，每请求为零次或一次，加密推理恢复时最多两次 |
| 停用原因 | 启用开关关闭的事件原因，用于展示与审计，不是独立恢复条件 |

Codex 的根会话及其子线程可以共享 `session_id`，而 `thread_id` 表示具体线程。账户粘连不按真实用户跨会话延伸；同一用户新建会话可以分配其他账户。

## 4. 账户启停与凭证

账户只保留一个启用开关，对应“启用”和“停用”两种调度状态。

以下情况将账户置为停用，并记录原因：

- 管理员关闭。
- 确认 5h 额度耗尽。
- 确认 7days 额度耗尽。
- OAuth 确认失效。

只有管理员主动打开开关才能恢复启用。额度重置、重新授权成功、定期额度查询均不得自动启用账户。不实现自动恢复或定时重新启用。

正常 Access Token 到期可以通过 Refresh Token 更新；确认授权无法继续使用时停用。临时网络故障、超时和普通请求失败不直接等同于 OAuth 失效，分类依据需要在上游适配中明确。

凭证加密保存，同一账户的刷新操作互斥。启用开关变化、授权更新及停用原因变化均记录时间、来源和关联请求。凭证值不得进入日志或审计正文。

## 5. 调度与排队

| 条件 | 行为 |
|---|---|
| 新会话存在可用账户和并发容量 | 分配账户、原子建立绑定并发送 |
| 同组存在可用账户但暂时没有容量 | 限时排队，获得容量后分配 |
| 已绑定账户启用且各级并发有容量、当前线程空闲 | 使用原绑定发送 |
| session 并发已满或同一 thread 有在途请求 | 限时排队；其他空闲线程可在 session 上限内执行 |
| 已绑定账户启用但并发已满 | 在原账户队列等待 |
| 已绑定账户停用 | 尚未发送的请求重新调度，并建立新绑定代次 |
| 空分组、同组账户全部停用或没有支持模型的账户 | 立即拒绝，HTTP 503 / `no_available_account`，不建立 SSE |
| 同组没有可用迁移目标 | 立即结束等待；已建立 SSE 则发送 `response.failed` 后关闭 |
| 可用迁移目标暂时满载 | 在等待时限和资源预算内继续排队 |
| 上游请求已经发出后失败 | 结束并记录错误；仅明确拒绝加密推理状态时可按第 8 节受限恢复 |

调度要求：

- 会话间轮转调度，同一线程内部保持请求顺序；不同线程共享可配置的 session 并发上限（默认 2，范围 1–1000），避免一组子线程占满账户。等待中的忙线程不阻塞其他空闲线程。
- session 按网关 Key 隔离；该上限不代表同一人的总并发。独立请求不按 Key 或缓存键合并成会话。
- 初次绑定与迁移提交完成后才能放行同会话的其他线程，所有线程共享一个绑定代次。
- 每账户并发可配置，排队时不占用并发槽，真正派发时占用。
- 并发槽覆盖整个上游请求生命周期，直到结束或取消清理完成，不在收到响应头时提前释放。
- 队列同时限制数量和内存占用，图片及大请求也计入预算。
- 等待请求只驻留内存；绑定和身份映射持久化。进程重启后不后台补发排队请求。
- 客户端断开，立即撤销等待；已经派发则取消本地上游读取并清理。
- 本地取消不能据此证明官方停止计算；没有最终 usage 时标记用量未知或不完整。
- 迁移不重置原入队时间，最长等待时限覆盖整个排队过程。
- 每个等待请求在全局容量与队列顺序检查前重新校验分组和账户可用性；Key 改组/停用、移走最后一个同组账户等变更会唤醒等待者。派发前再次检查 Key 与账户归属，已发出的上游调用按原归属完成。

### 停用与迁移的并发边界

默认停用阻止新的派发，已发出的请求允许收尾。对于需要迁移的同一会话，先等待旧代次的所有在途请求结束或取消，再派发新代次请求。

出队时重新检查启用状态、绑定代次和容量，原子确定本次请求的账户与映射，并占用并发槽。账户选择与身份改写以该派发结果为准，不能使用入队时已经过期的快照。

同一会话的多个等待请求共同观察迁移结果，不得分别建立互相冲突的代次。管理员恢复原账户后，已迁出的会话不会自动迁回。

账户候选范围先由模型目录和能力校验确定。未来增加提供方后，自动迁移仍限定在同一提供方和兼容接入方式内；跨厂商切换不属于普通账户迁移，也不通过重新绑定来绕过上下文兼容性检查。

## 6. 入站身份与上游映射

### 客户端来源

来源识别先于字段改写，结果仅使用入站客户端特征和元数据；unknown 是正常来源。有无会话独立判断，缓存键不作为来源或会话的证明。当前来源规则注册 Codex；后续扩展其他客户端规则不改变通用入站和上游适配边界。

账户 `codex_only` 默认 false。路由、等待及发送前都按原始识别结果检查账户来源限制；同组无符合来源条件的候选账户立即拒绝。限制影响账户资格，可在旧代次收尾后迁到同组允许的账户；已派发请求不因开关变化而取消。

### 入站身份

识别 Codex `0.153.4` 的对应字段：

- HTTP 头：`session-id`/`session_id`、`thread-id`/`thread_id`，兼容 `conversation-id`/`conversation_id`。
- 请求体：`client_metadata.session_id`、`client_metadata.thread_id`。
- 完整 turn 元数据：`client_metadata["x-codex-turn-metadata"]` 中的身份字段，以及 HTTP 中的兼容投影。

多个位置提供同一身份字段时必须一致；冲突返回明确的参数错误。只检查语义相同的重叠身份字段，不要求整个元数据对象完全相同。

明确 session 缺失时依次用 conversation、thread 兜底；缓存键不再作为会话标识；thread 缺失时用 conversation 或已解析的 session。不同语义的会话、线程、缓存键不要求相同，同一字段的别名仍必须一致。全部稳定字段缺失时按独立请求放行，不按 IP、UA、Key 或提示词猜测真实会话。临时调度范围仅存活于本次请求，不创建持久会话或映射；临时调度身份不发给上游；未提供的可选身份字段与缓存键保持省略。显式缓存键在账户与 Key 范围内稳定隔离，与是否建立会话无关。保留上游自动前缀缓存和真实用量统计。安装 ID、UA、IP 不作为粘连主键。

### 绑定代次

```text
Key 命名空间 + 客户端 session_id
    → 当前绑定代次
        → account_id
        → 上游 session_id
        → 客户端各 thread_id 及其他关联 ID 的映射
```

客户端会话与线程保持不变，迁移示例：

```text
客户端 S / T
    第 1 代 → 账户 A → S-A1 / T-A1
    第 2 代 → 账户 B → S-B2 / T-B2
    第 3 代 → 账户 A → S-A3 / T-A3
```

同一代次内映射稳定；每次迁移新建代次，即使切回曾使用的账户也不恢复旧映射。历史映射保留用于溯源，不能继续作为新代次的客户端会话身份；旧版本发出的正文对象别名仅用于还原上游原始 ID。

绑定及映射同时关联提供方和接入方式。首版中的 `session_id`、`thread_id` 等具体字段由 Codex 入站/上游适配器解释，核心维护通用客户端身份和映射关系，不要求未来所有提供方具有同名字段。

### 必须统一转换的身份

- `session_id`、`thread_id`、`turn_id`。
- `window_id`、`context_window_id`。
- 父线程、父 turn、根 turn、fork 来源等关联 ID。
- `x-client-request-id`、`prompt_cache_key`。
- 上述身份在 HTTP 头、请求体平铺元数据和嵌套 turn 元数据中的各处投影。

映射按类型和关系维护，不能每个字段分别随机生成。根会话中需要相等的标识保持相等，父线程引用指向新代次对应线程，工具调用与结果保持配对。

安装标识和认证身份采用目标账户的客户端配置。按 2026-09-18 用户明确选择，所有客户端传入的 `x-codex-turn-state` 继续丢弃，仅在请求详情采集原值，不向上游转发、不跨请求复用、不生成替代值。上游每次响应的该字段也独立记录；普通 Responses 不向客户端回传，Compact 保留既有回传逻辑。该观察不改变调度、恢复或生成行为，也不对模型质量作推断。

### 消息、工具与上游对象引用

身份换代仅覆盖客户端会话元数据。正文中的 item ID、call ID、response ID 和 SSE 引用保持上游原值；加密内容可能绑定这些 ID，不能重新生成。

消息、工具调用及结果按原 ID 保持配对，旧版本生成的客户端对象别名在同一网关 Key、会话和提供方范围内还原为原始上游 ID。加密 reasoning、加密 compaction、加密工具参数和内部内容元数据连同其原始对象 ID 一起透传，即使会话切换账户也不按本地来源记录拦截。网关不解密、不计算或保存内容摘要；是否能够使用由上游处理。

仅携带官方对象 ID 的引用及账户相关图片引用仍属于首版不支持的协议能力，要求客户端携带显式内容；不静默丢弃上下文。网关不保存正文，不能自行补出缺失历史。

## 7. 账户级请求归一化

每账户维护稳定的出站客户端配置，包括兼容版本、安装标识、HTTP/TLS 配置、连接池和凭证上下文。凭证刷新不随机更换安装或会话身份。

出站请求采用允许列表构造：下游认证、Cookie、UA、来源、内部身份头和内部追踪信息不直接用作上游值。网关从账户配置、绑定代次和请求上下文重建必需字段及实际提供的可选身份投影，不强行补齐缺失的会话、turn、窗口或缓存键。

2026-09-17 缓存兼容补充：独立 Responses 请求显式提供缓存键时，出站 `session_id`、`conversation_id` 复用缓存键的稳定隔离值，以对齐 sub2api OAuth 缓存关联头。该出站协议映射不改变入站会话语义、调度范围、来源识别或持久绑定；未提供缓存键时仍不生成会话头。

`input`、`instructions`、工具定义和结果、图片、模型、推理参数、Fast 选择属于业务语义，按协议保留。不能通过改写这些内容降低表面差异。第 8 节的加密推理恢复仅在上游明确拒绝后清理指定推理状态。

归一化目标是减少客户端配置杂乱、每请求随机更换标识及跨账户复用旧身份。它不会减少真实请求数量，也不承诺官方无法区分网关与 Codex 客户端。客户端源码不能用于推定服务端全部检测逻辑或所谓安全请求阈值。

## 8. HTTP/SSE 生命周期

```text
接收、鉴权、校验
    → 排队并维持客户端连接
    → 出队、确认账户与代次、占用并发槽
    → 构造最终上游请求并发送（符合恢复条件时至多补发一次）
    → 转发响应，同时完成必要的 ID 转换和用量提取
    → 正常结束、失败或取消
    → 清理连接、释放并发槽、记录最终状态
```

流式请求允许在排队时提前建立 SSE，并发送网关心跳。心跳采用 `: xxgate.queue_heartbeat request_id=…` SSE 注释，不发送 `data:` / `event:`，使按 SSE 数据事件计算首字的中间层忽略保活帧。长期等待仍需通过实际调用链验证。

心跳不伪造官方已创建响应或生成内容，不计为 Token、模型输出或首 Token。分别统计排队耗时、上游首事件耗时、上游首内容耗时及总耗时。

SSE 开始后不能再修改 HTTP 状态或追加官方响应头。排队失败和上游 HTTP 错误按明确的转换规则输出 `response.failed`，随后关闭流，不发送成功完成事件。原始上游状态、请求 ID 和额度头保存在审计与账户统计中。

上游 SSE 错误按协议处理，中途断开记录流中断；不伪造 `response.completed`，也不靠重新连接补完输出。

Codex 对部分错误可能按自己的策略重新请求，这是新的入站请求。这些客户端重发与下述网关恢复分别记录。

### 加密推理恢复

Responses 首次上游 HTTP 状态为 400、错误体的 `error.code` 精确等于 `invalid_encrypted_content`，且已准备的 `input` 中存在 reasoning 条目的 `encrypted_content` 字段时，才允许清理并补发一次。不根据错误文案猜测，也不处理 HTTP 200 内的 `response.failed`、连接错误、超时、Search 或独立 Compact。

清理仅移除 reasoning 的 `encrypted_content` 及该条目的空 `content`；保留 ID、摘要、非空内容与扩展字段，条目若只剩 type 则删除。其他输入、压缩块和工具参数密文原样保留。丢弃的加密推理状态无法在本次上下文中恢复，因此这是有损兼容恢复，不证明不同账户的密文一定兼容或一定不兼容。

补发使用原账户、凭证、绑定、身份映射和派发时价格，持续占用同一并发槽与线程锁。发送前重新检查取消、Key、账户分组/启停/来源/模型范围及模型路由，失效即结束，不换号补发。第二次无论何种结果都不再恢复。

首个 400 在网关内消费，不转发为下游失败事件。每次收到的上游响应头记录尝试序号、HTTP 状态、该次响应头耗时和上游请求 ID；恢复审计只记录触发分类和清理数量。单条请求的上游状态指最后一次尝试，总耗时与首事件/首内容耗时包含恢复前的等待；只按最终上游提供的实际用量计价，不为拒绝请求虚构用量。

## 9. 用量、价格与额度

### 用量与人民币金额

- 上游用量事实、网关计价结果、官方额度快照分开保存，不能互相推算替代。
- 记录输入、输出、缓存输入、推理等上游提供的明细，并保留计量来源。
- 明细字段与总量存在包含关系时避免重复累加。
- 失败或中断但已经取得的实际用量仍然记录；未发往上游的排队失败为明确未执行。
- 已发往上游但最终用量缺失时标记未知或不完整，不能记为零。
- 价格直接配置人民币，金额使用定点十进制；精度和舍入方式待确定。
- 模型名称可从各账户的上游获取并汇总，价格页直接选择名称，补填输入、缓存、输出与图片计量单价。
- Fast 使用该模型标准价格乘以可配置倍率，不单独填写另一套 Fast 单价。
- Fast 的请求档位、上游实际档位分别记录，档位不明确时不凭空认定额外费用。
- 每请求关联计价版本，历史金额不因后续改价被静默重算。
- 支持按账户、Key、模型、模式和时间聚合，不提供终端用户钱包、充值或扣款系统。

模型目录、计价和用量预留提供方及接入方式维度，裸模型名不作为全局唯一标识。各提供方分别解释缓存、推理、图片等字段及累计/增量口径，再形成通用计量项；服务档位和 Fast 参数不跨提供方强行套用。

### 5h / 7days 额度

保存上游报告的额度池、使用比例、窗口长度、重置时间、采集时间和数据来源。请求返回时更新，低频查询补充；查询端点、频率及兼容性待验证或配置。

额度过期或缺失标记为未知。本地流水只反映经过网关的请求，不能准确归因账户在其他渠道的消耗。

确认额度耗尽时关闭账户开关。额度恢复只更新观测信息，不能自动重新启用账户。

底层使用通用额度池、作用范围和窗口表示；5h/7days 是首版 Codex 的需求与展示方式。未来不提供这些窗口的上游显示不支持或未知，不能视为零额度或据此关闭账户。普通速率限制与确认的账户额度耗尽分别分类。

## 10. 观测与审计

每请求记录网关 `request_id`，上游调用存在时关联上游请求 ID。Codex 的 `x-client-request-id` 在该 HTTP 路径中等于线程 ID，不能替代逐请求主键。

记录范围：

- Key 命名空间、入站会话关联、账户、绑定代次和出站映射关联。
- 排队原因、队列进出时间、选路依据、迁移原因、并发槽占用。
- 客户端配置和归一化规则版本，哪些字段被移除或重建。
- 下游 HTTP 状态、网关业务终态、上游 HTTP 状态分别记录，不能以 SSE 的 HTTP 200 判定成功。
- 连接、上游首事件、首内容、总耗时，以及超时、失败、断开和取消阶段。
- 上游 usage、计量完整性、Fast 档位、价格版本和分项金额。
- 账户启停、额度快照、凭证维护结果、管理员操作和配置变更。

请求审计全量保存，性能遥测可采样。请求和会话 ID 不作为 Prometheus 指标标签。错误也必须脱敏，防止上游错误夹带正文或凭证。

管理员视图围绕总览、账户列表与详情、请求时间线、用量费用、模型价格、Key、配置与审计组织。

## 11. 配置与立即生效

### 已确认默认值

| 参数 | 默认值 |
|---|---:|
| 单 session 并发上限 | 2（同一 thread 串行） |
| 最长排队时间 | 5 分钟 |
| 排队心跳间隔 | 10 秒 |
| 上游连接超时 | 15 秒 |
| 上游 SSE 空闲超时 | 5 分钟 |
| 请求明细保留期 | 30 天 |
| 管理员审计保留期 | 180 天 |

以上参数及并发、队列数量和内存上限均可配置、热更新，无需重启。数量与内存预算的初始值根据部署机器确定。

### 热更新语义

| 配置项 | 已有任务的处理 |
|---|---|
| 最长排队时间 | 按原入队时间重新计算期限，超过新期限立即结束等待 |
| 心跳间隔 | 已建立的排队 SSE 采用新间隔 |
| 上游连接超时 | 正在连接的请求按原连接开始时间重新计算期限 |
| 上游 SSE 空闲超时 | 按最近一次有效上游事件重新计算期限，网关心跳不算上游事件 |
| session / 账户 / 全局并发、队列数量、内存上限 | 上调立即增加准入容量；下调立即限制新增占用，存量请求继续收尾 |
| 数据保留期限 | 策略立即生效并触发清理，实际删除异步执行并展示进度 |

配置先校验、持久化，再发布到运行时。保存成功表示新配置版本已生效。记录修改前后值、版本、管理员和时间，请求记录影响其执行的配置变更。

已有等待或超时计时器必须响应变更，不能只让新请求读取新值。重算期限以原始时间点为基准，不从保存配置的时刻重新开始计时。

新的超时规则可能立即结束已有请求，但不会触发网关重试或重放。配置更新不在上游已发出的请求中途替换账户或身份代次。

## 12. 技术实现方向

首版采用 Rust 模块化单体，建议组合为 Tokio、Axum、SQLx、PostgreSQL，观测采用 tracing 与 OpenTelemetry。调度及队列在进程内运行，首版不要求 Redis 或多实例协调。

代码目录、模块职责、依赖方向、运行状态所有权及验证归属详见 [代码模块规划](modules.md)。首版规划一个 workspace、五个 crate：

- `xxgate-core`：核心业务规则和用例编排，内部按账户、调度、身份、协议契约、提供方能力、用量、价格、配置等职责分模块。
- `xxgate-codex`：内部拆分 `ingress` 与 `provider`，分别适配 Codex/Responses 入站协议和 Codex 0.153.4 上游；共享纯编解码模块。
- `xxgate-transport`：出站 HTTP、连接池、TLS、取消和可更新的传输超时控制。
- `xxgate-postgres`：持久化、事务、查询和 schema migration。
- `xxgate-server`：服务装配、HTTP/管理员入口、遥测和后台任务生命周期。

三个适配 crate 依赖核心定义的端口，核心不反向依赖具体协议、HTTP 框架或数据库驱动。只有服务入口负责装配全部实现，不按每个功能拆服务。

核心分别定义入站适配与上游提供方适配端口，二者通过通用请求/事件及有来源约束的专有扩展交换信息。未来增加 `xxgate-anthropic`、`xxgate-gemini` 时无需依赖 Codex crate；首版不创建这些 crate 或空实现。不支持的能力和无法转换的上下文明确报错，不静默丢弃。

Codex 出站传输对齐 `0.153.4` 的选定基线。该版本 HTTP 客户端直接使用 reqwest `0.12.28`，锁文件还包含其他依赖链引入的 reqwest 版本，不能据此混用。此客户端特征约束不强制套用到未来其他提供方，其传输和认证配置各自独立。

需要一起核对编译 features、实际 TLS 后端、目标运行平台、连接及压缩行为。该版本有默认 TLS 路径和可选 rustls 路径，不能仅凭存在 rustls 依赖认定所有请求都使用相同 TLS 构造。

不能直接复用 Codex 全部请求控制流程：其 HTTP 路径存在授权恢复重试，而 XXGate 只允许上文定义的加密推理恢复，不允许授权恢复后的生成重放。依赖和协议兼容与网关的调用次数约束分别验证。

## 13. 待确定与待验证

### 待确定的配置或范围

- 每账户并发、全局与账户队列数量、总内存预算和请求大小上限的初始值。
- 额度查询频率、额度数据过期判定和统计汇总保留期。
- 金额精度、舍入方式和具体模型价格。
- 同一 session 下不同 thread 的并行与顺序细节，避免破坏 Codex 子线程关系。
- 核心 Responses 接口之外，模型发现、`/responses/compact` 等辅助接口是否纳入首版。
- `stream=false` 的对外行为与所需的上游适配范围，不能静默将非流式调用改成对外 SSE。

### 必须完成的验证

- Codex `0.153.4` 直连的身份提取、头部和元数据一致性。
- 长时间排队、注释心跳、排队失败事件、客户端取消及客户端自行重请求。
- 提前返回 SSE 之后，上游非成功 HTTP 状态和响应头信息的处理。
- 账户并发满时等待、停用时迁移、迁移屏障和多个等待请求的竞争。
- A 到 B 再到 A 的全部身份换代，含父子引用、输入消息、工具配对、SSE 增量及最终对象。
- OAuth 上游实际可用的图片输入、生成、编辑能力与计量信息。
- 账户迁移时官方对象引用、图片引用、加密 reasoning/compaction 的可迁移边界。
- 配置热更新对既有队列、连接、SSE、资源准入及清理任务的即时影响。
- 进程异常退出后的绑定恢复、未知用量记录以及不补发请求的行为。

以上为原始验证清单。已完成的本地单元/模拟上游集成验证与尚未完成的真实账户验证见 [实现与验证记录](implementation.md)。
